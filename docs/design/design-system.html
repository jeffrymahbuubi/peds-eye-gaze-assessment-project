The visual system proposed for the Pediatric Eye-Gaze Assessment desktop app (PySide6/Qt): the operator pages a clinician uses and the task canvas a child looks at. Every value on this page is taken from the proposal; nothing in the app changes until a SPEC written from it is approved.

Direction

Carbon's visual grammar (flat surfaces, 4 px corners, one border weight, a strict 4 px spacing grid, a type scale with few steps, tokens with roles, AA baked in) reads as a measuring instrument rather than a dashboard template. The NHS service manual adds what Carbon lacks: plain-language rules, field width by content length, and error and status wording for staff under time pressure. The child-facing canvas keeps its own rules, derived from contrast and timing measurements, because no design system covers a gaze canvas.

What stays from today

  • The page flow, the WTMH blue family as the single accent, and Segoe UI (so the app reads as native Windows, not as a web template).
  • The amber practice bar, the run bar's word + colour tracking state, the run-end dialog logic.
  • Visual-angle target sizing, the dwell and switch logic, the shortcuts Alt-P, Alt-Q, Esc and H.

Specimen stack on this page: "Segoe UI", "Open Sans", "Noto Sans", system-ui, sans-serif. On Windows you see the real Segoe UI; elsewhere Open Sans (Google Fonts) stands in. Sizes are true px at 100 % scale.

Canvas (child-facing)

The feedback ladder is cue < on-target < success, measured against the forest field #e8f5e9 (and the space field #0d1b2a). The theme YAML gains explicit keys for every colour the canvas draws, so no colour is derived from cursor_color with an alpha any more. The cue is strong in form (the only outlined, filled, saturated shape) and in luminance; red and green distractors differ by only 1.33:1 in luminance, so for a child with a colour-vision deficiency the outline, not the hue, is the cue.

Target sizes at 1:2

Diameters from the proposal's copy table: Small 3° about 124 px, Medium 5° 207 px. Large is 8° in the app; its px value is not stated in the proposal (about 331 px at the same 41.4 px per degree, derived). Drawn at half size on a 1920x1080 field strip, with the two-tone outline: 3 px #102010 outside, 2 px white inside, following the shape.

The ladder, Medium target at 1:2

Cue. Flat fill #D32F2F (4.43:1 on the field), two-tone outline that follows the shape. Distractors #5F8F66, no outline (3.33:1).
On-target. One ring at r + 10, 6 px, #1b5e20 (7.00:1); the dwell arc at r + 16, 8 px, white core on a #102010 halo, fills over threshold_ms. Gaze cursor unchanged: #102010 halo, white core, r 5.
Glow (Switch and Follow only). From the outline to r + 0.3 r, alpha 160 to 0, #2E7D32 (4.56:1 at its edge), capped at half the distance to the nearest slot.
Success. The fill turns #2E7D32 for 500 ms, outline stays; 12 particles, 8 px, 500 ms. Success is the only event that changes the target itself, so it is the loudest.

Grid cells, square targets, the follow trail and Space

Grid. Cell outline 2 px #5F8F66, fill white alpha 16. The outline and the ring are built from shape_path at r + offset, so a square target gets a square ring.

Timing

The on-target ring appears on the first on-target frame and disappears on the first off-target frame, no ramp. The dwell arc fills over threshold_ms as today (0.8 s default). Success lasts 500 ms, inside the 800 ms default inter-trial interval, so it never delays the next trial. Nothing else moves.

Copy rules

  • No em dash in any label, option or sentence. A colon for a definition, a comma or parentheses for a qualifier, a full stop between sentences.
  • One date format: yyyy-MM-dd, and yyyy-MM-dd HH:mm (24-hour) when a time is shown.
  • One vocabulary: the configuration page is the source of truth; the report and the PDF repeat its words. Units follow the value, not the label.
  • No interpunct chains. Facts are separate elements (chip, text, badge) or separate sentences.
  • Status words are nouns or past participles, never exclamations: "Test complete", "Blocked", "Not done".
  • A page title names the object and has no colon: "Summary Results", "Detailed Results".

Implementation phases

Each phase is one SPEC step with its own acceptance checks. Order matters: later phases use earlier tokens. The path is a QSS token port, keeping the PySide6 widgets, the object names and the qt-mcp harness.
